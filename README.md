# Swiggy Case Study: Customer Journey & Engagement Analysis (SQL)

An SQL-driven product-analytics case study that follows the Swiggy customer
journey (sign-up -> first order -> repeat -> churn) and turns raw order data
into insights for recommendations, loyalty programs and roadmap planning.

> **Data note:** Swiggy does not publish order-level data. This project uses a
> **simulated, seeded dataset** (2,500 customers, 150 restaurants, 600 menu items,
> ~16.6k orders across 5 cities, Jan-Dec 2024) generated by `src/generate_data.py`.
> The SQL and methodology are real and reusable; swap the CSVs in `data/` for
> real or public data to get real conclusions.

## What this project answers

| # | Query (`sql/`) | Business question | SQL concepts |
|---|---|---|---|
| 1 | `q01_inactive_users` | Who has gone quiet for 60+ days (win-back list)? | CTE, joins, date math |
| 2 | `q02_repeat_customers` | How much revenue comes from repeat customers? | `CASE`, window `SUM() OVER` |
| 3 | `q03_favorite_food_per_customer` | What is each customer's favourite food? | `ROW_NUMBER() OVER (PARTITION BY ...)` |
| 4 | `q04_top_foods` | Which dishes drive revenue and breadth of demand? | multi-table joins, aggregation |
| 5 | `q05_top_restaurants_by_city` | Who are the top-performing restaurants per city and do customers come back? | `RANK() OVER (PARTITION BY ...)` |
| 6 | `q06_mom_revenue_growth` | How are revenue, AOV and orders trending month over month? | `LAG()` |
| 7 | `q07_cohort_retention` | How well are monthly cohorts retained? | cohort analysis, self-joins |
| 8 | `q08_rfm_segments` | Which customer segments matter most? | `NTILE()` RFM scoring |
| 9 | `q09_order_timing` | When do people order (daypart, weekday/weekend)? | `CASE`, `strftime` |
| 10 | `q10_discount_vs_retention` | Does a discounted first order improve retention? | window + conditional aggregation |

## Key insights (on the simulated data)

- **Repeat customers carry the business:** customers with 10+ orders are 20.9% of the base but 58.2% of revenue; one-time customers are 26.6% of customers and only 4.2% of revenue.
- **Growth is decelerating:** monthly revenue grew from ~INR 0.28 lakh in January to ~9.5 lakh in December; MoM growth fell from double digits to 2.5-7.8% in Nov-Dec.
- **Retention:** the January cohort retains ~53% after 1 month and ~47% after 11 months. Early-month churn is the biggest leak.
- **Win-back pool:** 820 customers (about a third of the base) have not ordered in 60+ days. Sorting by lifetime spend gives a prioritised list.
- **Segments:** "Champions" (840 customers) generate ~3.99M of revenue; the "At Risk" group (392 customers, avg 7.8 orders, quiet ~99 days) is the highest-value win-back target.
- **Timing:** lunch (11-15) and dinner (19-22) produce most orders; weekday dinner is the largest slot. AOV is flat (~INR 375-390) across dayparts.
- **Food:** Pepperoni and Farmhouse Pizza lead revenue; favourite-food analysis shows strong clusters (Chicken Biryani, Farmhouse Pizza, Chocolate Brownie) useful for recommendations.
- **Discounts:** a discounted first order did not improve repeat rate (72.9% vs 73.6% for full price), which suggests first-order discounts may be over-spent. (In this simulated data discounts were assigned at random, so treat this as an example of how to test the question, not a finding about Swiggy.)

## Product recommendations
1. **Recommendations:** use favourite-food and cuisine affinity (Q3/Q4) to power "order again" and personalised rows.
2. **Loyalty:** reward the 5-9 order band to push them toward 10+, where most revenue sits.
3. **Win-back:** trigger campaigns at 45-60 days of inactivity, prioritising "At Risk" customers.
4. **Promotions:** test discount depth and targeting before scaling first-order offers.
5. **Supply:** staff and promote around lunch and dinner peaks.

## Structure
```
.
├── data/                      # 5 CSVs (customers, restaurants, menu_items, orders, order_items)
├── sql/                       # 10 analysis queries (SQLite dialect)
├── src/
│   ├── generate_data.py       # builds the simulated dataset
│   ├── run_analysis.py        # loads SQLite, runs queries, saves tables + charts
│   └── run_all.py
├── outputs/
│   ├── query_results/         # one CSV per query
│   └── figures/               # charts
└── requirements.txt
```

## Run it
```bash
pip install -r requirements.txt
python src/run_all.py
```
Queries are plain SQLite (window functions require SQLite 3.25+). You can also run any `.sql` file directly against `outputs/swiggy.db`.

## Schema
`customers(customer_id, city, signup_date)` · `restaurants(restaurant_id, name, city, cuisine, rating)` · `menu_items(item_id, restaurant_id, item_name, price)` · `orders(order_id, customer_id, restaurant_id, order_ts, status, discount_amount, delivery_fee, total_amount)` · `order_items(order_id, item_id, quantity, unit_price)`

## Tools
SQL (SQLite), Python, Pandas, NumPy, Matplotlib
